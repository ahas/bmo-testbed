# bmo-testbed

여러 호출자와 여러 저장소가 함께 쓰는 한 대의 머신을 위한 범용 테스트베드입니다. 무거운 테스트·빌드 명령을 모두
받는 하나의 큐, 변경 선택 기능이 있는 전체 스위트 러너, 빠른 정적 검사, 그리고 저장소를 자신이 도는 머신에
릴리스 단위로 배포하는 기능을 제공합니다.

- **아는 것은 메커니즘뿐입니다.** 어떤 저장소도 이름으로 알지 않습니다. 테스트베드를 쓰는 저장소는 테스트, 검사,
  빌드, 배포 방법을 루트의 파일 하나, `testbed.toml`(`docs/declaration.md`)에 선언하며, 저장소마다 다른 것은 모두
  그곳에 둡니다.
- **제공하는 것은 바이너리 하나**, `bmo-testbed`와 그것을 이루는 크레이트들, 그리고 도구 호스트가 실행하는 도구
  하나 `testbed/deploy`입니다. 하네스의 세션은 이 도구로 커밋을 라이브에 올립니다. 동사, 종료 코드, 읽는 환경
  변수, 읽는 선언, 보내는 이벤트, `serve`가 띄우는 HTTP 서비스, `mcp`가 띄우는 하네스 플러그인, 호스팅 배포 도구,
  그리고 이들이 묻는 배치 엔드포인트가 경계의 전부이며(`docs/boundary.md`), 라우트와 도구는 `docs/openapi.json`에
  정리되어 있습니다.
- **업스트림입니다.** 하네스는 다른 것을 아무것도 띄우지 않은 상태에서 MCP 서버와 `bmo-testbed` 스킬을 통해 이를
  첫 진입점으로 삼습니다.
- **다른 저장소에는 의존하지 않습니다.** 예외는 기반 라이브러리인 `bmo-chat`, `bmo-chat-client`,
  `bmo-console-face`, `bmo-text`, `bmo-ui`뿐이며, 소비하는 쪽은 테스트 키트를 dev-dependency로 가져갈 수 있습니다.

| `docs/backup.md` | 데이터 백업: 무엇을, 어디에, 얼마나 자주 백업하는지, 로테이션, 복원 훈련, 수동 복원, 설정 |
| `docs/declaration.md` | `testbed.toml` 스키마 |

## 구조

| 폴더 | 내용 |
|---|---|
| `core/` | 큐, 레인, 차례, 실행과 그 결과, 언어, 메모리 한도, 선언 리더, 정책 로더 |
| `suite/` | 전체 스위트 러너, 변경 선택, 정적 검사, 빠른 검사, Cargo 동사, 빌드 디렉터리 정리 |
| `deploy/` | 릴리스, 배포 트리 링크, 유닛 링크, 배포 실행, 진행 상황, 롤백, 백업 |
| `backup/` | 데이터 백업: 머신의 데이터베이스와 데이터 폴더를 덤프하고 묶어서 목적지로 보내고, 로테이션하고, 복원 훈련으로 되살립니다 |
| `cli/` | `bmo-testbed` 바이너리: 각 동사의 인자를 읽어 크레이트에 넘깁니다 |
| `client/` | 공개 클라이언트: HTTP 서비스의 멤버, 쿼리, 오류 코드와 각 라우트를 호출하는 클라이언트 |
| `record/` | 모든 동사가 쓰고 서비스가 읽는 기록: 테스트 실행, 배포, 로그 줄, 재시작, 이벤트 |
| `service/` | 기록과 레인 위의 HTTP 서비스와 그 이벤트 스트림 |
| `plugin/` | 하네스 플러그인: MCP 서버의 도구, OpenAPI 문서, `bmo-testbed` 스킬 |
| `tools/` | 도구 호스트가 실행하는 도구. 각각 매니페스트와 입력 스키마를 곁들인 크레이트이며, `deploy`는 하네스 세션을 위해 커밋을 라이브에 올립니다 |
| `test-support/` | Rust 테스트가 사람, 방, 유닛을 가리킬 때 쓰는 고정 id. 테스트 키트의 것과 같습니다 |
| `scratch-database/` | 소비자의 마이그레이터가 만든 템플릿에서 복제하는 테스트별 PostgreSQL 데이터베이스 |
| `testkit/` | 소비자가 미리 불러오는 TypeScript 테스트 키트: 테스트 홈과 대역들 |
| `units/` | 이 저장소의 배포가 관리하는 사용자 유닛: Cargo 빌드 디렉터리 정리, 데이터 백업의 스냅샷·미디어·훈련, 각 타이머, 그리고 테스트베드가 시작하거나 배포하는 모든 유닛이 도는 slice |
| `policy/` | `core`의 정책 로더가 읽는 테스트베드 자체의 고정 수치와 문구 |
| `docs/` | 위의 문서들 |

루트에는 버전을 담은 Cargo 워크스페이스 매니페스트와 그 lockfile, 포매터 설정, 이 저장소 자체의 `testbed.toml`,
그리고 `CLAUDE.md`가 있습니다.

## 버전

- **저장소 전체에 버전 하나,** 워크스페이스의 버전이며 `docs/boundary.md`가 정하는 경계에 대해 매깁니다. 첫
  릴리스 전까지는 `0.1.0`에 `-rev.N` 리비전을 붙이고, 그 뒤로는 시맨틱 버저닝을 따릅니다(`docs/boundary.md`,
  「Versions」).
- **선언은 자신이 대상으로 하는 메이저 버전을 밝히며,** 다른 메이저의 테스트베드는 그 선언을 거부합니다. 그래서
  소비하는 쪽은 의도적으로만 새 메이저로 옮겨 갑니다.
