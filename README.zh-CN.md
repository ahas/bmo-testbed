# bmo-testbed

一个通用测试台，服务于由多个调用方和多个仓库共享的一台机器：为所有重型测试和构建命令提供统一队列，提供带变更选择的
全量测试套件运行器、快速静态检查，以及将仓库按版本发布部署到其所在机器上的能力。

- **它只了解机制。** 它不按名称认识任何仓库。使用它的仓库在根目录下的一个文件 `testbed.toml`
  （`docs/declaration.md`）中声明如何测试、检查、构建和部署，各仓库之间的所有差异都写在那里。
- **它提供的是一个二进制文件** `bmo-testbed`、构成它的各个 crate，以及工具主机运行的一个工具 `testbed/deploy`，
  harness 的会话通过它把一次提交上线。它的命令、退出码、读取的环境变量、读取的声明、发送的事件、`serve` 启动的
  HTTP 服务、`mcp` 启动的 harness 插件、托管部署工具以及它们查询的放置端点，构成了它的全部边界
  （`docs/boundary.md`），路由和工具列于 `docs/openapi.json`。
- **它是上游：** harness 在不运行任何其他东西的情况下，通过它的 MCP 服务器和 `bmo-testbed` 技能把它作为第一个入口。
- **它不依赖任何其他仓库，** 只有基础库 `bmo-chat`、`bmo-chat-client`、`bmo-console-face`、`bmo-text` 和 `bmo-ui`
  除外；使用方可以把它的测试工具包作为 dev-dependency 引入。

## 布局

| 目录 | 内容 |
|---|---|
| `core/` | 队列、通道、轮次、运行及其结果、语言、内存限制、声明读取器和策略加载器 |
| `suite/` | 全量套件运行器、变更选择、静态检查、快速检查、Cargo 命令以及构建目录清理 |
| `deploy/` | 发布版本、部署树链接、单元链接、部署运行、进度、回滚和备份 |
| `backup/` | 数据备份：将机器上的数据库和数据目录导出、打包、发送到目的地、轮换，并通过演练进行恢复 |
| `cli/` | `bmo-testbed` 二进制：读取每个命令的参数并交给各个 crate |
| `client/` | 对外发布的客户端：HTTP 服务的成员、查询和错误码，以及调用每个路由的客户端 |
| `record/` | 每个命令写入、服务读取的记录：测试运行、部署、日志行、重启和事件 |
| `service/` | 建立在记录和通道之上的 HTTP 服务及其事件流 |
| `plugin/` | harness 插件：MCP 服务器的工具、OpenAPI 文档和 `bmo-testbed` 技能 |
| `tools/` | 工具主机运行的工具，每个都是附带清单和输入 schema 的 crate：`deploy` 为 harness 的会话把一次提交上线 |
| `test-support/` | Rust 测试用来指代人员、房间和单元的固定 id，与测试工具包中的相同 |
| `scratch-database/` | 每个测试专用的 PostgreSQL 数据库，从使用方迁移器创建的模板克隆而来 |
| `testkit/` | 使用方预加载的 TypeScript 测试工具包：测试主目录和替身 |
| `units/` | 本仓库的部署所维护的用户单元：Cargo 构建目录清理，数据备份的快照、介质和演练，它们的定时器，以及测试台启动或分发的每个单元所运行的 slice |
| `policy/` | 测试台自身的固定数值和文字，由 `core` 的策略加载器读取 |
| `docs/` | 上述文档 |

根目录下有保存版本号的 Cargo 工作区清单及其锁文件、格式化工具的设置、本仓库自己的 `testbed.toml`，以及
`CLAUDE.md`。

## 版本

- **整个仓库只有一个版本，** 即工作区的版本，针对 `docs/boundary.md` 所述的边界而定：首次发布前为 `0.1.0` 加上
  `-rev.N` 修订号，此后遵循语义化版本（`docs/boundary.md`，「Versions」）。
- **声明会写明它所针对的主版本，** 其他主版本的测试台会拒绝它，因此使用方只会有意识地迁移到新的主版本。
