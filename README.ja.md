# bmo-testbed

多くの呼び出し元と多くのリポジトリが共有する一台のマシンのための、汎用テストベッドです。重いテスト・ビルドコマンドを
すべて受け付ける一つのキュー、変更選択付きのフルスイートランナー、高速な静的チェック、そしてリポジトリを自身が動く
マシンへリリース単位でデプロイする機能を提供します。

- **知っているのは仕組みだけです。** どのリポジトリも名前では知りません。テストベッドを使うリポジトリは、テスト、
  チェック、ビルド、デプロイの方法をルートの一つのファイル `testbed.toml`(`docs/declaration.md`)で宣言し、
  リポジトリごとに異なることはすべてそこに書きます。
- **提供するのは一つのバイナリ**、`bmo-testbed` とそれを構成するクレート群、そしてツールホストが実行するツール
  `testbed/deploy` 一つです。ハーネスのセッションはこのツールでコミットを本番に反映します。動詞、終了コード、読み込む
  環境変数、読み込む宣言、送出するイベント、`serve` が起動する HTTP サービス、`mcp` が起動するハーネスプラグイン、
  ホスト型デプロイツール、そしてそれらが問い合わせる配置エンドポイントが境界のすべてであり(`docs/boundary.md`)、
  ルートとツールは `docs/openapi.json` にまとめられています。
- **アップストリームです。** ハーネスは他に何も動かしていない状態で、MCP サーバーと `bmo-testbed` スキルを通じて
  これを最初の入口とします。
- **他のリポジトリには依存しません。** 例外は基盤ライブラリの `bmo-chat`、`bmo-chat-client`、`bmo-console-face`、
  `bmo-text`、`bmo-ui` だけで、利用側はテストキットを dev-dependency として取り込めます。

## ドキュメント

| ドキュメント | 内容 |
|---|---|
| `docs/testbed.md` | キュー: レーン、順番、先頭と次、待機、幅、結果行、言語、配置 |
| `docs/suite.md` | フルスイートの実行: スイープ、レーン、フェンス、テストデータベース、失敗した実行の一回の再実行、毎日のフル実行 |
| `docs/checks.md` | 変更がどのテストを実行するか、静的チェック、クイックチェック、変更チェック、インポート、テスト数 |
| `docs/deploy.md` | リリース、採用、ユニットのマーク、デプロイの実行、進捗、ホスト型デプロイツール、ロールバック、拒否、バックアップ、Cargo のビルドディレクトリ |
| `docs/backup.md` | データバックアップ: 何を、どこへ、どの頻度でバックアップするか、ローテーション、リストア訓練、手動でのリストア、設定 |
| `docs/declaration.md` | `testbed.toml` のスキーマ |
| `docs/boundary.md` | すべての動詞、終了コード、ステータスフィールド、環境変数、イベント、記録、HTTP サービス、ハーネスプラグイン、ホスト型デプロイツール、配置エンドポイント、バージョンのルール |
| `docs/openapi.json` | コードから生成した HTTP サービスのルートとメンバー、およびハーネスプラグインのツール |
| `docs/PERSONAL-DATA.md` | このリポジトリに決して含めてはならないもの(人の名前、住所、パス、デバイスやネットワークの情報、エージェントや製品の名前)と、それを防ぐチェック |

## 構成

| フォルダ | 内容 |
|---|---|
| `core/` | キュー、レーン、順番、実行とその結果、言語、メモリ上限、宣言リーダー、ポリシーローダー |
| `suite/` | フルスイートランナー、変更選択、静的チェック、クイックチェック、Cargo 動詞、ビルドディレクトリの整理 |
| `deploy/` | リリース、デプロイツリーのリンク、ユニットのリンク、デプロイの実行、進捗、ロールバック、バックアップ |
| `backup/` | データバックアップ: マシンのデータベースとデータフォルダをダンプしてまとめ、送信先に送り、ローテーションし、リストア訓練で復元します |
| `cli/` | `bmo-testbed` バイナリ: 各動詞の引数を読み取り、クレートに渡します |
| `client/` | 公開クライアント: HTTP サービスのメンバー、クエリ、エラーコード、各ルートを呼び出すクライアント |
| `record/` | すべての動詞が書き込み、サービスが読む記録: テスト実行、デプロイ、ログ行、再起動、イベント |
| `service/` | 記録とレーンの上に立つ HTTP サービスと、そのイベントストリーム |
| `plugin/` | ハーネスプラグイン: MCP サーバーのツール、OpenAPI ドキュメント、`bmo-testbed` スキル |
| `tools/` | ツールホストが実行するツール。それぞれマニフェストと入力スキーマを伴うクレートで、`deploy` はハーネスのセッションのためにコミットを本番に反映します |
| `test-support/` | Rust のテストが人、ルーム、ユニットを指すための固定 ID。テストキットのものと同じです |
| `scratch-database/` | 利用側のマイグレーターが作ったテンプレートから複製する、テストごとの PostgreSQL データベース |
| `testkit/` | 利用側が事前に読み込む TypeScript のテストキット: テスト用ホームと代役 |
| `units/` | このリポジトリのデプロイが管理するユーザーユニット: Cargo ビルドディレクトリの整理、データバックアップのスナップショット・メディア・訓練、それぞれのタイマー、そしてテストベッドが起動または配布するすべてのユニットが動く slice |
| `policy/` | `core` のポリシーローダーが読む、テストベッド自身の固定値と文言 |
| `docs/` | 上記のドキュメント |

ルートには、バージョンを持つ Cargo ワークスペースのマニフェストとそのロックファイル、フォーマッタの設定、この
リポジトリ自身の `testbed.toml`、そして `CLAUDE.md` があります。

## バージョン

- **リポジトリ全体で一つのバージョン**、つまりワークスペースのバージョンで、BMO セットのバージョンでもあります。
  オーナーがセット全体のリリースを宣言したときにだけセマンティックバージョニングに従って動き、リリースの間の
  デプロイはその日のナイトリーの名前で呼ばれます(`docs/boundary.md`、「Versions」; `docs/deploy.md`、
  「The deployed version」)。
- **宣言は自分が従うスキーマのメジャーを明記し、** 別のメジャーを読むテストベッドはその宣言を拒否します。そのため
  利用側は意図したときにだけ新しいスキーマへ移行し、セットのバージョンはこのメジャーを動かしません。
